# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

- **Job-first verification and company-state refactor.** Made the primary job-search journey job-first: Candidate → Search Criteria → Current Job Discovery → Current Job Verification → Candidate/Job Fit → Company State → Recruiter/Hiring-Manager Discovery → Outreach Prioritization, while preserving company-first research as a supported focused journey (`workflows/full-journey.md`).
- Added the [Job Record schema](schemas/job-record.schema.md) as a first-class logical record (identity, discovery, current-availability state, role requirements, candidate-fit-gate result, evidence/lifecycle) — no longer only nested evidence inside a Company or Activity Record; documented the migration/compatibility boundary against the pre-existing Activity Record `job_status` fields and the Company Record's `hiring_signal_status` in `core/data-model.md`.
- Added the [Company State Record schema](schemas/company-state-record.schema.md) for time-sensitive organizational developments (layoffs, hiring freezes, restructuring, acquisitions, funding, expansion, leadership changes, and similar), kept strictly separate from stable Company Record identity/classification and from Job Record availability, with Fact vs. Supported Inference impact labeling.
- Added the canonical [Current Job Verification Policy](core/job-verification-policy.md): source hierarchy (official careers site/ATS first), the mandatory official-site cross-check for secondary discoveries (LinkedIn, Glassdoor, Indeed, other job boards, recruiter posts, search snippets), the full verification-outcome table, and the "absence from an official careers search is not proof of closure" rule.
- Added the [Primary Job Eligibility Gate](ranking/job-eligibility-gate.md): a hard availability gate (Gate A) and hard candidate-fit gate (Gate B) a role must pass before entering the primary Verified Jobs Map — company attractiveness never substitutes for either gate; a role failing either gate becomes a Rejected Lead with a specific reason rather than being silently dropped.
- Added four new workflow modules — [Discover Jobs](workflows/discover-jobs.md), [Verify Job](workflows/verify-job.md), [Evaluate Candidate–Job Fit](workflows/evaluate-candidate-job-fit.md), and [Verify Company State](workflows/verify-company-state.md) — and the [Job Search Journey](workflows/job-search-journey.md) that orchestrates them as the new default full journey for job-discovery intent; updated `core/workflow.md`, `workflows/focused-task-routing.md`, and `workflows/resume-journey.md` accordingly.
- Added two new canonical outputs — the [Verified Jobs Map](outputs/verified-jobs-map-template.md) (primary job-search result, Verified Open and Likely Open/Partially Verified kept in clearly separate sections) and [Unverified and Rejected Job Leads](outputs/unverified-job-leads-template.md) (every rejected role kept visible with a specific reason) — plus matching CSV column contracts, and extended the Outreach Queue output/CSV contract with an Associated Job Record column.
- Updated `core/source-policy.md`, `core/freshness-policy.md`, `core/quality-gates.md`, `core/output-contracts.md`, `core/product-definition.md`, and `core/scope-and-non-goals.md` to incorporate the job-first verification policy, company-state freshness (event date vs. checked-at vs. currency), and the new quality gates (no job-board/recruiter-post/search-snippet alone can produce Verified Open; a closed or hard-constraint-failing role cannot enter the primary map; company-state facts stay separated from impact inference; a layoff does not auto-close every job at a company).
- Updated `schemas/research-state.schema.md` with four new independently-resumable/refreshable stage statuses (`job_discovery_status`, `job_verification_status`, `job_fit_evaluation_status`, `company_state_verification_status`); updated `schemas/activity-record.schema.md` and `schemas/company-record.schema.md` with cross-references documenting the new Job Record authority boundary.
- Regenerated all three platform packages from the updated canonical sources: added a ninth ChatGPT Knowledge bundle (`chatgpt/knowledge/09-job-and-company-state.md`) and updated the build/package scripts and manifests (`scripts/build-chatgpt-knowledge.sh`/`.ps1`, `scripts/package-chatgpt-gpt.sh`/`.ps1`); added a new Claude Skill reference (`claude/skill/references/job-intelligence.md`) and two new Skill templates (`verified-jobs-map.md`, `unverified-job-leads.md`); added `core/job-verification-policy.md` and `ranking/job-eligibility-gate.md` to the Claude external kit's Knowledge allowlist (`scripts/package-claude-external-kit.sh`/`.ps1`); updated Claude Project Instructions (full and compact, kept behaviorally aligned), the Skill trigger policy, state routing, artifact policy, and knowledge manifest.
- Added new smoke tests covering the job-first eligibility gate and company-state handling to `chatgpt/testing-guide.md` (Tests 10–13) and `claude/external-install/verification-guide.md` (Tests 6–7).

- Initialized repository foundation: project structure, working rules, and high-level scope.
- Defined the core candidate and research state data model: Candidate Profile, Search Criteria, and Research State schemas.
- Defined the Company, Person, and Activity Record schemas, extending the core data model to target companies, public professional contacts, and verified public activity evidence.
- Defined the shared trust policy: Source Policy, Confidence Model, Freshness Policy, and Quality Gates.
- Defined the ranking and outreach priority policy: Company Ranking Model, Person Ranking Model, Exclusion Policy, and Outreach Priority Model.
- Defined modular workflow orchestration: core workflow, Full Journey, Focused Task Routing, Resume Journey, and per-module definitions (Analyze Candidate, Build Search Criteria, Discover Companies, Classify and Rank Companies, Discover People, Verify Activity, Build Outreach Queue); aligned Research State stage names with the workflow modules.
- Defined canonical output contracts: Candidate Profile, Search Criteria, Company Map, Excluded Companies, People Map, Activity Verification, Outreach Queue templates, and stable CSV column contracts for each.
- Reconciled deferred schema gaps: added `stale_reason` and `refresh_required` to the Company, Person, and Activity Record schemas, and `duplicate_contact_group` to the Person Record schema.
- Added the Tova golden journey: a complete, fully synthetic end-to-end example exercising the candidate/research data model, trust policy, ranking models, workflow, and output contracts together.
- Reconciled the five specification gaps identified by the Tova golden journey: added a shared percentage-based scoring-band rubric to the Company and Person Ranking Models; defined company re-scoring triggers and process; made the manager-versus-recruiter outreach tie-break explicit with a complete 10-step tie-break sequence; clarified the distinct, coexisting roles of `duplicate_risk` and `duplicate_contact_group` on the Person Record; and expanded the Company Map output contract (Markdown and CSV) to surface all eight Company Ranking Model dimensions.
- Added the first installable Claude Skill package (`claude/skill/`): a `SKILL.md` entry point defining product purpose, journey support, and explicit non-actions; eight progressively-loaded reference files adapting the canonical candidate, company, people, activity, ranking/exclusion, workflow-routing, output-generation, and quality/trust methodology for Claude; and eight reusable, placeholder-only output templates.
- Defined progressive reference loading: routes each user intent to the minimum required Skill reference files instead of loading the full methodology for every request.
- Added deterministic macOS/Linux packaging (`scripts/package-claude-skill.sh`) and Windows PowerShell packaging (`scripts/package-claude-skill.ps1`), both building `dist/career-targeting-intelligence.skill.zip` from the same explicit file allowlist (`SKILL.md`, `references/`, `templates/`) with a single top-level package directory.
- Added the Claude Skill package manifest (`claude/skill-manifest.md`) and packaging guide (`claude/packaging.md`), documenting included/excluded files, canonical source mappings, expected ZIP structure, and cross-platform packaging parity.
- Added the Claude Project Experience: full (`claude/project-instructions.md`) and compact (`claude/project-instructions.compact.md`) Project Instructions defining product identity, Skill routing, Full/Focused/Resume journey support, active-context reuse, trust rules, output behavior, and explicit non-actions, kept behaviorally aligned by design.
- Added the Skill trigger policy (`claude/skill-trigger-policy.md`), distinguishing requests that require full Skill methodology, partial reference to existing results, or no Skill involvement.
- Added state routing (`claude/state-routing.md`), defining how the Project reuses active context, resumes only from an actually-available Research State, and scopes refreshes to only the affected modules.
- Added the Knowledge manifest (`claude/knowledge-manifest.md`), recommending shared methodology Knowledge files while excluding personal records and the Skill package itself from duplication.
- Added the artifact policy (`claude/artifact-policy.md`), aligning artifact generation with the canonical output contracts and lifecycle statuses.
- Added conversation starters (`claude/conversation-starters.md`) and a Project setup guide (`claude/project-setup.md`) with a layer-responsibility table spanning the core repository, Skill, Project Instructions, Project Knowledge, platform, and user.
- Added the Claude external self-install kit (`claude/external-install/`) for users outside the creator's Claude organization: installation documentation, a fixed shared-Knowledge allowlist, verification smoke tests, a privacy guide, and a package manifest describing the kit's exact archive structure.
- Added deterministic macOS/Linux packaging (`scripts/package-claude-external-kit.sh`) and Windows PowerShell packaging (`scripts/package-claude-external-kit.ps1`) for the external kit, both building the Skill ZIP first, then assembling `dist/career-targeting-intelligence-claude-kit.zip` around it with the canonical compact Project Instructions copied byte-for-byte and the approved Knowledge files copied byte-for-byte from their canonical sources.
- Documented the Organization Shared Project and External Self-Install as two distinct distribution paths in `claude/project-setup.md`, and the Skill ZIP versus External Kit ZIP as two distinct artifacts in `claude/skill-manifest.md` and `claude/packaging.md`.
- Added the initial ChatGPT Custom GPT package (`chatgpt/`): deployment-ready GPT Instructions (`chatgpt/instructions.md`) defining identity, supported journeys, the core routing rule, intent routing, context rules, clarification policy, research and evidence policy, ranking policy, output policy, next-step behavior, and explicit non-actions.

- Added deterministic Knowledge builders (`scripts/build-chatgpt-knowledge.sh`, `scripts/build-chatgpt-knowledge.ps1`) that regenerate the eight bundles from an explicit source allowlist, and are never hand-edited.
- Added Builder setup, testing, and sharing/publishing documentation (`chatgpt/builder-setup.md`, `chatgpt/testing-guide.md` with nine smoke tests including a Tova Golden Journey regression walkthrough, `chatgpt/sharing-and-publishing.md`) and a package manifest and deployment README (`chatgpt/package-manifest.md`, `chatgpt/README.md`).
